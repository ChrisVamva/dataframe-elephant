**Nanopublication Structure**

A nanopublication is a small, self-contained, citable unit of Linked Data that packages an atomic scientific claim together with its provenance and publication metadata. It is implemented using RDF named graphs (quads) and is designed for machine interpretation, verification, and reuse.

### Core Components (Four Named Graphs)

Every well-formed nanopublication consists of exactly four named graphs:

| Graph | Purpose | Content Rules | Typical Predicates |
|-------|---------|---------------|--------------------|
| **Head** | Structural container that identifies the nanopublication and links the other three graphs | Declares the nanopublication and points to Assertion, Provenance, and PublicationInfo | `rdf:type np:Nanopublication`, `np:hasAssertion`, `np:hasProvenance`, `np:hasPublicationInfo` |
| **Assertion** | The main scientific claim (atomic unit of knowledge) | One or more RDF triples expressing the claim | Domain-specific (e.g., gene–disease, drug–indication) |
| **Provenance** | How the *assertion* was generated (“how this came to be”) | MUST contain at least one reference to the assertion graph URI | `prov:wasDerivedFrom`, `prov:wasAttributedTo`, timestamps, methods, source DOIs |
| **Publication Info** | Provenance/metadata of the *nanopublication itself* | MUST reference the nanopublication URI; SHOULD include creator and timestamp | `dct:creator`, `dct:created`, `pav:createdBy`, license, versioning |

**Namespace**: `http://www.nanopub.org/nschema#` (prefix `np:`)

**Formal schema (OWL)**:
```turtle
np:Nanopublication rdf:type owl:Class .
np:Assertion rdfs:subClassOf rdfg:Graph .
np:Provenance rdfs:subClassOf rdfg:Graph .
np:PublicationInfo rdfs:subClassOf rdfg:Graph .

np:hasAssertion a owl:FunctionalProperty ;
  rdfs:domain np:Nanopublication ; rdfs:range np:Assertion .
np:hasProvenance a owl:FunctionalProperty ;
  rdfs:domain np:Nanopublication ; rdfs:range np:Provenance .
np:hasPublicationInfo a owl:FunctionalProperty ;
  rdfs:domain np:Nanopublication ; rdfs:range np:PublicationInfo .
```

### Minimal Well-Formed Example (TriG)

```turtle
@prefix : <http://example.org/pub1/> .
@prefix ex: <http://example.org/> .
@prefix np: <http://www.nanopub.org/nschema#> .
@prefix prov: <http://www.w3.org/ns/prov#> .
@prefix dct: <http://purl.org/dc/terms/> .
@prefix orcid: <https://orcid.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

:Head {
  : a np:Nanopublication .
  : np:hasAssertion :assertion .
  : np:hasProvenance :provenance .
  : np:hasPublicationInfo :pubinfo .
}

:assertion {
  ex:trastuzumab ex:is-indicated-for ex:breast-cancer .
}

:provenance {
  :assertion prov:wasDerivedFrom :experiment .
  :assertion prov:wasAttributedTo orcid:0000-0003-3934-0072 .
}

:pubinfo {
  : dct:creator orcid:0000-0003-0183-6910 .
  : dct:created "2020-07-10T10:20:22.382+02:00"^^xsd:dateTime .
}
```

### Well-Formedness Criteria (MUST)

From the official guidelines:

- Consists of RDF quads (every triple has a graph/context URI; no null graphs).
- Exactly one quad of the form `[N] rdf:type np:Nanopublication [H]`.
- Exactly one each of `np:hasAssertion`, `np:hasProvenance`, and `np:hasPublicationInfo` linking from the nanopublication URI in the head graph.
- The five URIs (nanopublication, head, assertion, provenance, publication-info) are all distinct.
- All triples appear in one of the four graphs.
- Provenance graph contains ≥1 reference to the assertion graph.
- Publication-info graph contains ≥1 reference to the nanopublication URI.

### Integrity and Immutability (Trusty URIs)

After the content is finalized, a **Trusty URI** (content-hash-based identifier) is typically attached. This makes the entire nanopublication (including all graphs) immutable and verifiable. The Trusty URI becomes the permanent identifier of the nanopublication.

Example with Trusty URI (abbreviated):
```turtle
@prefix this: <http://example.org/pub1/RA-0Yc_l8rK3_Ts8y7kPuZvg6FqzaOSSq0yMSS9Sg4R9I> .
@prefix sub: <http://example.org/pub1/RA-0Yc_l8rK3_Ts8y7kPuZvg6FqzaOSSq0yMSS9Sg4R9I#> .

sub:Head {
  this: a np:Nanopublication ;
        np:hasAssertion sub:assertion ;
        np:hasProvenance sub:provenance ;
        np:hasPublicationInfo sub:pubinfo .
}
# ... assertion, provenance, pubinfo graphs follow with sub: prefixes
```

### Extended Structure (Multi-Source Claims)

For claims aggregated from multiple sources (information extraction, truth discovery, etc.), an optional fifth named graph can be added:

- **Knowledge Provenance graph** – Uses the PROV-K ontology to record supporting vs. conflicting evidence, truth values, reliability criteria, and trust relationships.

This extension remains backward-compatible with the standard four-graph model.

### Recommended Serialization and Querying

- **Preferred syntax**: TriG (compact named-graph RDF).
- **Querying**: SPARQL over quad stores. A standard template extracts an entire nanopublication by starting from the head graph and following the `np:has*` links.
- Common additional vocabularies: PROV-O, PAV, Dublin Core Terms, ORCID identifiers, domain ontologies (SIO, etc.).

### Position in Research-to-Data Workflow

Nanopublications sit primarily at the **Structured representation → Normalization / Database → Provenance** stages. They turn extracted claims into immutable, citable, provenance-rich units that can be queried, aggregated, cited, and reused by later analysis, visualization, interpretation, and agent-iteration steps.

**Primary source**: Official Nanopublication Guidelines (working draft) at https://nanopub.net/guidelines/working_draft/ and the `nschema` ontology.
