# Findings

_Date-stamped findings by research question. Every finding cites `[S##]`. Claim types follow the Research-Evaluation protocol: `[documented fact]` / `[reported signal]` / `[inference]`. Research pass of 2026-10-11._

## RQ1 — Taxonomy and scope: what counts as "memory"

- `[documented fact]` Agent "memory" is not one mechanism but at least six — session/context, explicit instruction files, searchable history, summarised/compacted state, extracted memory records, and knowledge/temporal graphs — with different lifetimes, scopes, and control surfaces `[S01, S17, S37, S09, S07, S06]`.
- `[documented fact]` Shipping **coding agents** are dominated by the *instruction-file* layer: Claude Code layers `CLAUDE.md` files plus machine-written auto memory `[S17]`; Cline uses a `memory-bank/` convention it re-reads each session `[S22]`; Cursor, Copilot, Aider, Zed, Continue, JetBrains, and Amazon Q document instruction files and **no persistent memory store** `[S18–S22, S28–S32]`.
- `[documented fact]` Agent-written persistent memory is now common in coding tools: at least **six** ship it — Claude Code auto memory `[S17]`, Codex Memories `[S24]`, Gemini CLI Auto Memory `[S27]`, **Kiro Memory** `[S96]`, **Devin Memory** `[S100]`, and legacy Windsurf Cascade `[S23]` — with Cursor Projects a partial seventh `[S102]`.
- `[documented fact]` They **converge on one design**: a `MEMORY.md` entry point plus Markdown notes on disk, consolidated in the background ("dreaming", "auto memory", "automatic memory updates"). Claude Code, Devin, Hermes, OpenClaw, Kiro, and this project's own agent all use a `MEMORY.md` file or index `[S17, S82, S88, S96, S100]`.
- `[documented fact]` Scope is the second axis and is explicit in some tools: Claude auto memory is keyed to the **git repo** and stored machine-locally `[S17]`; Windsurf memories are workspace-associated and never committed `[S23]`; Codex memory is local under `~/.codex/memories/` `[S24]`; service memory is scoped by `user_id`/`agent_id`/`run_id` `[S07]`.
- `[documented fact]` The **autonomous/personal-agent tier** adds a seventh pattern — local-first Markdown memory on disk: Hermes uses bounded `MEMORY.md`/`USER.md` files plus FTS5 session search and a journey graph `[S82]`; OpenClaw uses `MEMORY.md`, daily `memory/YYYY-MM-DD.md` notes, `USER.md`, and `DREAMS.md`, with a "dreaming" distiller and an automatic memory flush before compaction `[S88]`. Both are plain files the user can read and edit, and both are on by default `[S82, S88]`.
- `[inference]` The user-facing phrase "what it remembers" is therefore ambiguous for a single product — it can mean a human-authored file (inspectable, user-owned) *and* a machine-extracted record (often not inspectable) `[S17, S07]`. This is the category error the CAM pitch flagged.

## RQ2 — Mechanisms and failure modes

- `[documented fact]` The **write decision** is the least-standardised stage. Mem0 extracts facts, dedupes, embeds, and is additive unless `update`/`delete` is called `[S07, S15]`; Letta block updates "replace the entire block content rather than appending" `[S04]`. Same label ("memory"), opposite overwrite semantics.
- `[documented fact]` Consolidation is lossy and background-executed: Anthropic's compaction summarises a near-limit conversation and warns aggressive compression "can lose subtle critical context" `[S09]`; Letta's "Dreaming" and LangMem's background manager consolidate lessons with no user-visible diff `[S04, S05]`.
- `[documented fact]` Effective context is far below nominal: RULER finds "almost all models exhibit large performance drops as the context length increases," with only half of 17 long-context LMs satisfactory at 32K `[S11]`; Lost in the Middle shows middle-of-context degradation `[S12]`; Chroma's Context Rot shows performance "grows increasingly unreliable as input length grows" `[S10]`.
- `[documented fact]` The long-context-vs-retrieval literature is unresolved: one paper reports long context beating RAG at sufficient resources but costing far more `[S14]`; another reports long contexts losing focus on an "inverted U-shaped curve" favouring retrieval `[S13]`.
- `[inference]` Long context **delays** the memory problem rather than removing it — selective storage/retrieval stays necessary because effective context is small, position matters, and cost scales with tokens `[S11, S12, S10, S13, S14]`.
- `[inference]` A seven-part failure taxonomy falls out of the evidence: staleness (F1), silent compaction loss (F2), retrieval imprecision (F3), confabulated/inferred-as-fact memory (F4), poisoning (F5), cross-boundary bleed (F6), and non-determinism (F7) `[S06, S04, S09, S12, S15, S79, S65, S68]`.

## RQ3 — Product reality

- `[documented fact]` Consumer assistants default memory **on**: Copilot memory needs "no action … to turn on" and "Enhanced personalization is turned on by default" `[S40]`; ChatGPT memory reached Free/Plus/Team/Enterprise during 2024–25 `[S36]`; Gemini requires "Memory turned on" for saved instructions to apply `[S39]`.
- `[documented fact]` Copilot stores memory in the user's **Exchange mailbox** in a hidden folder, Purview retention policies "don't apply," admins "can't restrict what type of information is added," and memory actions "don't generate audit log entries" `[S40]` — the memory layer sits outside existing audit/DLP.
- `[documented fact]` Enterprise platforms ship the richest controls: Azure AI Foundry (preview) offers item-level CRUD, store-level TTL, and direct remember/forget with quotas (100 scopes, 10,000 memories/scope) `[S46]`; Vertex Memory Bank records memory **revisions** under IAM, VPC-SC, CMEK, and residency `[S45]`.
- `[reported signal]` Infrastructure-vendor benchmark claims are self-reported and non-comparable: Mem0 (vendor paper `[S15]`), Zep (LoCoMo 94.7% / LongMemEval 90.2% `[S54]`), Redis ("86.5%" `[S56]`) each report against different subsets, and none is reproduced under a shared protocol; a June 2026 TechCrunch summary of two Writer papers argues memory can *degrade* outputs but gives no figures `[S51]`.
- `[reported signal]` Mem0 raised a reported $24M with undisclosed valuation and company-supplied adoption figures `[S50]`; Letta's announcement states no funding amount `[S53]`.
- `[documented fact]` The **personal-agent tier is the best-governed**: Hermes stages memory writes for approval and prints every overwritten/removed entry `[S82]`; OpenClaw exposes `memory status/search/index`, an incognito mode that writes no transcript, and per-conversation scoping with opt-in cross-conversation recall `[S88, S89]`. Both keep memory on disk ("there is no hidden state") and store it on the user's own hardware `[S82, S87]`.
- `[documented fact]` Recent entrants confirm the trend rather than lagging it: **Kiro Memory** documents access levels *read & write / read only / off* and "Automatic memory updates," gated behind Kiro CLI V3 `[S96]`; **Devin Memory** is on by default, personally scoped, Git-backed, and pruned by "dreaming" `[S100]`.
- `[reported signal]` **Field note (single observation, 2026-10-12).** A practitioner who has used Kiro, Devin, and Cursor reported not encountering agent-written memory comparable to their current tool. The docs only partly support this: Kiro's Memory is very recent (docs updated 2026-10-09, V3-gated) `[S96]` and Devin's Memory is a newer first-class feature `[S100]`, so the impression is plausibly a snapshot of an earlier state. Treat as a lead for re-testing, not as evidence of absence.
- `[inference]` The market has **three** control realities, not two: **local-first open agents** (files on disk, approval/audit, self-hosted) `[S82, S88]` > **enterprise platforms** (CRUD/TTL/revisions) `[S46, S45]` > **consumer assistants** (default-on, soft delete, no audit) `[S40, S37]`. The CAM privacy concern lands hardest on the consumer tier and least on the self-hosted agents — the opposite of a capability ranking.

## RQ4 — Control, privacy, and security

- `[documented fact]` **Deletion is soft and non-local.** Turning ChatGPT memory off does not delete past chats; deleted saved-memory logs may persist up to 30 days; deleting a memory does not remove its mentions elsewhere `[S37]`. Claude documents view/edit but no explicit delete `[S47]`. GDPR Art. 17 has no mechanism for derived memory — summaries, embeddings, graph edges `[S61, S64]`.
- `[documented fact]` A user-visible memory **change log** is rare and tier-dependent. Copilot explicitly generates none `[S40]`, and no cloud product examined exposes one; **Hermes is the exception** — its approval flow "lists the full text of every entry it overwrote or removed," and background writes are tagged `[auto]` `[S82]`. The gap is thus a property of cloud memory, not of memory as such.
- `[documented fact]` Self-hosting is not automatically safer: OpenClaw is the named target of the MemCollusion poisoning study (81.3% save / 75.0% success) `[S69]`, and a separate study frames it as a "continuously running, skill-augmented system with persistent memory" exposed to skill poisoning and cascading failures `[S94]`; Hermes' security docs admit its eight-layer guards are "not a hard boundary" `[S84]`.
- `[documented fact]` The Council of Europe **draft** (T-PD(2025)3rev4) would require memory-off-by-default, cross-layer deletion "including caches and vector stores," separate read vs create/modify/transmit/delete permissions, agent inventories, revocable credentials, and a human review point `[S64]` — reported via secondary source only.
- `[documented fact]` Enforcement precedent exists but is unsettled: the Garante fined OpenAI €15M (Nov 2024) with a rectification/deletion order `[S63]`; the decision was temporarily removed after a March 2026 court judgment `[S63]`. The EDPB holds that models trained on personal data cannot automatically be called anonymous `[S58]`.
- `[documented fact]` Memory poisoning is a **named, benchmarked attack class**: AgentPoison (<0.1% poison rate, >80% ASR) `[S66]`, MINJA (query-only poisoning) `[S65]`, MemoryGraft (persistent behavioural drift) `[S67]`, Salami/MemCollusion (81.3% save / 75.0% success) `[S69]`, PipePoison (survives eight defenses) `[S71]`, Mind Your HEARTBEAT (pollution without prompt injection) `[S70]`.
- `[documented fact]` Cross-tenant leakage is demonstrated: MemLeak shows cross-user semantic leakage through "ordinary similarity retrieval" on a shared vector store; ownership gating restored the baseline `[S68]`.
- `[inference]` **Provenance is the missing control.** Both the privacy failure (erasure cannot find derived copies `[S61, S64]`) and the security failure (consolidation launders low-trust content, up to 1.000 ASR without provenance `[S79]`) trace to records that do not carry where they came from.

## RQ5 — Evaluation and record design

- `[documented fact]` Mainstream benchmarks measure **utility only**: LoCoMo (long-dialogue QA) `[S73]`, LongMemEval (five abilities, ~30% accuracy drop over sustained interaction) `[S74]`, MemoryAgentBench (four competencies incl. selective forgetting) `[S75]`, MemBench (factual vs reflective) `[S76]`. None tests poisoning, leakage, or erasure.
- `[documented fact]` Security-oriented evaluation is emerging: MemSecBench finds harmful memory persisted in **84.2%** of cases, full write-to-execute in **50.3%**, selective repair in **56.1%** `[S77]`; MemSentry gates writes with 91.7% reported accuracy `[S78]`; PPMF shows provenance loss drives ASR to 1.000 `[S79]`; MemGauge frames utility vs risk `[S80]`.
- `[inference]` A **benchmark mismatch** is the field's structural problem: vendors cite recall leaderboards `[S15, S16, S54]`, while the security literature shows the same class of system failing write-time integrity `[S77, S79]`. High recall and a poisonable, leaky store are not mutually exclusive.
- `[inference — design]` The governance gap is addressable with existing primitives: enterprise memory stores already have CRUD/TTL/revisions `[S46, S45]`, the MCP memory server already has explicit delete/search ops `[S34]`, and research already models provenance/versioning `[S03, S79]`. A **Memory Governance Record** v0 (`../05_Memory_Record_Design/`) turns these into one envelope: append-don't-overwrite, monotone trust classes, scope-enforced retrieval, tombstones that propagate, and a visible write history.

## Method limits (carry into any article)

- **Vendor-documentation bias:** nearly every product claim rests on a **C** source; the vendor's own docs are the only public description of its memory. Treat product capabilities as vendor claims until reproduced.
- **Self-reported benchmarks:** Mem0/Zep/Redis figures come from vendor-authored papers or vendor pages and are not comparable `[S15, S16, S51, S54]`.
- **2026-dated security preprints** (`[S67, S68, S69, S70, S71, S72, S77, S78, S79, S80]`) were located during the 2026-10-11 pass; figures are paper-reported and not independently replicated here.
- **Draft law:** the Council of Europe instrument is a draft and was located via secondary reporting only `[S64]`.
- **No disclosed real-world incident** of memory poisoning or cross-tenant leakage was found; all evidence is lab/benchmark `[S72, S68]`.
- **Second pass (group H):** the autonomous/personal agent platforms (Hermes, OpenClaw) were added on 2026-10-11; their product facts rest on self-published docs plus repo metadata, with the one independent evaluation being the MemCollusion paper `[S69, S81–S95]`. No independent memory benchmark of Hermes was located `[S86]`.
- **Correction (third pass, 2026-10-12):** two first-pass rows were incomplete — Devin (only the legacy Cascade caveat had been recorded) and Cursor (the absence of a branded "Memories" feature masked agent-written Projects context) — and Kiro was missing entirely. Corrected via `[S96–S103]`.
