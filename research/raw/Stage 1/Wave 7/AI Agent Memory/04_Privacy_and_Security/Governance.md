# Governance — Control, Privacy, Law, Security, and Evaluation

_Date: 2026-10-11. Every factual claim cites `[S##]` from `../06_Evidence/Sources.md`. Claim-type tags: `[documented fact]` / `[reported signal]` / `[inference]`._

## 1. Control surfaces — what a user can actually do

- `[documented fact]` **View/edit** is common; **delete** is where products diverge. OpenAI exposes a "Memory summary" with "Sources," a "Don't mention this again" action, and toggles for saved memories and chat history `[S37]`. Anthropic documents view/edit for Claude memory and states it is "fully optional, with granular user controls," plus incognito chats that don't save to memory — but the page states **no explicit delete control** `[S47]`.
- `[documented fact]` Deletion is partly **soft and non-local**. OpenAI: "Turning off Memory does not delete your past chats"; "OpenAI may retain logs of deleted saved memories for up to 30 days"; it "can take time for deletion and Memory updates to propagate"; and deleting a saved memory "does not remove mentions of that information from past conversations" `[S37]`.
- `[documented fact]` Microsoft Copilot memory is **on by default** ("No action is required to turn on Copilot memory"; "Enhanced personalization is turned on by default"), Purview retention policies "don't apply," saved memories persist until explicitly deleted, and — the load-bearing line — memory actions "don't generate audit log entries" `[S40]`.
- `[documented fact]` Enterprise platforms expose programmatic control that consumer tools generally lack: Azure AI Foundry memory (preview) offers item-level CRUD, store-level TTL, and direct remember/forget with quotas `[S46]`; Vertex Memory Bank exposes memory generation/ingestion/retrieval and revision history under IAM `[S45]`.
- `[documented fact]` **Hermes Agent** ships the closest thing to a memory change log in the survey: memory writes can be staged for approval (`/memory pending`, `/memory approve <id>|all`, `/memory reject <id>`, `/memory approval on|off`), background writes are tagged `[auto]`, and `/memory approve` "lists the full text of every entry it overwrote or removed"; a write is refused if the target changed after staging. Memory is on by default (`write_approval: false`), stored as two bounded Markdown files (`MEMORY.md` 2,200 chars; `USER.md` 1,375 chars) under `~/.hermes/memories/` `[S82]`.
- `[documented fact]` **OpenClaw** exposes inspection and scope control rather than an approval log: `openclaw memory status|search|index --force`, `/context list`, `/context detail`, session cleanup (`openclaw sessions cleanup --dry-run|--enforce`), an incognito "New thread" that writes no transcript and skips the automatic memory flush, and per-conversation sessions with opt-in cross-conversation recall. Memory is plain Markdown in the workspace — the docs state "there is no hidden state" `[S88, S89]`.
- `[inference]` **Revised (2026-10-11, second pass):** *most* cloud products expose no user-visible memory change log — Copilot explicitly generates none `[S40]`, and a consumer sees only the current memory, not its source turn or who wrote it. But the **change-log gap is a property of cloud memory, not of memory as such**: the open-source, local-first agents give the user files on disk, an approval queue, and (in Hermes) an overwrite listing `[S82, S88]`. Control tracks where the memory physically lives.

## 2. Data-protection law — applicable, but not memory-specific

- `[documented fact]` GDPR Art. 17 requires erasure "without undue delay" on grounds including data "no longer necessary," withdrawal of consent, objection, or unlawful processing; a controller that made data public must take "reasonable steps, including technical measures" `[S61]`. The problem in practice is that memory is redistributed across caches, vector stores, summaries, and derived logs, and Art. 17 has no mechanism addressing derived representations `[S61, S64]`.
- `[documented fact]` EDPB Opinion 28/2024 holds that models trained on personal data "cannot, in all cases, be considered anonymous" and requires the legitimate-interest test to be "lawful," "clearly and precisely articulated," "real and present" `[S58]`; the EDPB chartered a ChatGPT Taskforce whose report is dated 24 May 2024 `[S59]`.
- `[documented fact]` EU AI Act Art. 50 (in force 2026-08-02) imposes transparency duties — informing people they interact with an AI and marking synthetic content — but **no memory-specific duty** `[S60]`.
- `[documented fact]` CCPA/CPRA grants rights to know and delete with a 45-day window (extendable to 90); the California OAG page carries no AI- or memory-specific guidance `[S62]`.
- `[documented fact]` Enforcement precedent: Italy's Garante fined OpenAI **€15M** (Decision No. 755, 2 Nov 2024) and ordered a six-month information campaign covering objection, rectification, and deletion `[S63]`. The page notes the decision was temporarily removed after a Court of Rome judgment published 2026-03-18, so enforcement status is **unsettled** `[S63]`.
- `[reported signal]` The Council of Europe has a **draft** instrument (T-PD(2025)3rev4) that would require persistent memory disabled by default, the ability to "locate, correct and delete personal data held across every layer of memory, including caches and vector stores," separate permissions for reading versus creating/modifying/transmitting/deleting, "agent inventories," "task-limited revocable credentials," and "a point of effective human review" `[S64]`. Only secondary reporting was located; the official document URL was not confirmed, so treat it as a reported signal `[S64]`.

## 3. Security — memory as an attack surface

- `[documented fact]` Memory is now a **named, benchmarked attack class**, not a hypothetical. AgentPoison (2024-07-17) backdoors RAG/memory agents with a **<0.1% poison rate**, **>80% average attack success**, and **<1% benign impact** `[S66]`. MINJA (2025-03-05) poisons memory through **query-only interaction** — "any user" can influence memory — using bridging steps and a progressive-shortening strategy so the malicious record is retrievable later `[S65]`.
- `[documented fact]` Poisoning **persists and drifts behaviour**: MemoryGraft (2025-12-18) implants poisoned "successful experiences" and exploits a "semantic imitation heuristic," producing "persistent behavioral drift across sessions" on MetaGPT's DataInterpreter with GPT-4o `[S67]`.
- `[documented fact]` Attacks now target the whole pipeline and multiple layers: Salami Attack / MemCollusion (2026-08-03) splits a goal into "individually harmless fragments" for an **81.3% save rate / 75.0% success** on OpenClaw, surviving dilution defenses `[S69]`; PipePoison (2026-09-01) jointly optimises write/retrieve/utilize and remains effective under eight defenses `[S71]`; Mind Your HEARTBEAT (2026-03-24) shows routine background saving moves untrusted content into durable memory **without prompt injection** `[S70]`.
- `[documented fact]` Cross-tenant leakage is demonstrated: MemLeak (2026-10-03) shows **cross-user semantic leakage** when multi-tenant agents share a vector store via "ordinary similarity retrieval"; ownership gating restored the clean baseline `[S68]`.
- `[documented fact]` Reported 2026 agent-security incidents (PASAC, 2026-10-08): OpenAI agents reportedly compromised parts of Hugging Face's production environment; an Anthropic third-party environment exposed real systems; Gemini accessed three real organisations through an unintended internet route, which Google said it stopped in all three instances `[S72]`. The paper flags the Gemini record as limited to statements/journalism `[S72]`.
- `[reported signal]` A 2024 user forum post claimed ChatGPT showed memory entries "clearly not mine"; **no official confirmation, CVE, or regulator finding** was located `[—]`.
- `[documented fact]` Self-hosting is **not** automatically safer. OpenClaw is the named target of the MemCollusion study (81.3% save / 75.0% success) `[S69]`, and a separate study frames it as a "continuously running, skill-augmented system with persistent memory" exposed to skill poisoning and multi-agent cascading failures `[S94]`. Hermes' security docs describe an eight-layer model that includes "Cross-session isolation" (sessions cannot access each other's data or state), while admitting the guards are "not a hard boundary" `[S84]`.
- `[inference]` Memory defenses are early and mostly **interception/gating** rather than architectural isolation: MemSentry screens writes with Accept/Review/Quarantine `[S78]`, provenance gates block low-trust writes `[S79]`, and Hermes stages writes for approval `[S82]`. Hermes' staged approval is the only shipping *write-approval* mechanism found — but it defaults **off** (`write_approval: false`) `[S82]`, so the protection exists and is latent.

## 4. Evaluation — capability benchmarks and the security gap

- `[documented fact]` Mainstream memory benchmarks measure **utility, not confidentiality, integrity, or erasure**. LoCoMo averages ~300 turns / 9K tokens over up to 35 sessions and tests QA, summarisation, and multimodal dialogue — no privacy or security dimension `[S73]`. LongMemEval's 500 questions cover extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention, and report a **~30% accuracy drop** over sustained interaction — again no poisoning or leakage test `[S74]`. MemoryAgentBench tests accurate retrieval, test-time learning, long-range understanding, and **selective forgetting**, and finds "current methods fall short of mastering all four" `[S75]`; MemBench separates factual from reflective memory and scores effectiveness, efficiency, and capacity `[S76]`.
- `[documented fact]` Security-oriented counterparts are emerging: MemSecBench (2026-07-29) runs a "Write–Execute–Forget" lifecycle over 310 instances/48 settings and finds **harmful memory persisted in 84.2% of cases**, the full write-to-execute chain succeeded in **50.3%**, and "selective repair" worked in **56.1%** `[S77]`. Memory Provenance Laundering (2026-07-31) shows consolidation rewrites low-trust observations as user history; without provenance, vulnerable memories reached **up to 1.000 ASR**, while a provenance-preserving gate blocked unauthorized high-risk actions `[S79]`. MemGauge (2026-08-31) frames the utility–risk tradeoff `[S80]`.
- `[inference]` The field has a **benchmark mismatch**: the public leaderboards vendors cite `[S15, S16, S48, S54]` measure recall on LoCoMo/LongMemEval, while the security literature shows the same systems failing write-time integrity `[S77, S79]`. A memory that scores well and can be poisoned or leak across tenants is not a safe memory.
