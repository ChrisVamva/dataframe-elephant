# Research-to-Data Capability Cluster: Structured Research Brief

**Access date for all sources:** 2026-09-27  
**Scope:** Evidence-grounded map of the workflow Research → Evidence → Extraction → Structured representation → Normalization → Database → Query → Analysis → Visualization → Interpretation → New research → Agent iteration, across nine lenses. Claims are marked by type (documented fact, reported signal, inference, recommendation). Confidence reflects source strength and cross-validation.

---

## 1. Executive synthesis

- The workflow is not linear; feedback loops (especially Interpretation → New research and Agent iteration) dominate mature practice. Quality gates (provenance, tests, lineage) are the primary differentiators between ad-hoc analysis and reusable knowledge systems.
- **Boundaries are sharp on tools, fuzzy on roles.** DuckDB is an in-process OLAP engine (not a warehouse); dbt owns only the T in ELT; Knowledge Engineer roles range from ontology design to GenAI knowledge curation and are not interchangeable with Data Analyst or Analytics Engineer.
- **Extraction is the highest-friction stage.** Classical NLP (NER, relation extraction) and LLM-assisted pipelines (Unstructured, LlamaParse, EvidenceNet-style systems) coexist; provenance and multi-source truth discovery remain weak points.
- **Normalization + modeling** is the value inflection: raw evidence becomes queryable only after schema, ontology, or semantic-layer decisions. dbt + dimensional/medallion patterns dominate analytics; graph/ontology approaches dominate knowledge-intensive domains.
- **Query/Analysis split** is real: DuckDB/pandas/Polars for local/interactive; warehouse + dbt + BI (Metabase/Superset) for shared, governed analytics. Polars and DuckDB increasingly overlap on analytical workloads.
- **Agents** are emerging as orchestrators of the entire loop (research, extraction, cleaning, analysis) but currently excel at bounded sub-tasks; verification and failure modes (hallucination, incomplete provenance, non-deterministic extraction) are the main open risks.
- **Market signal:** Analytics Engineer (dbt-centric) has solidified between Data Engineer and Data Analyst; AI/agent workflow and Knowledge Engineer roles are rising but less standardized.
- **Open questions:** Stable provenance standards beyond PROV-O/nanopublications for LLM-derived claims; cost/quality trade-offs of LLM vs classical extraction at scale; whether agent frameworks (LangGraph, LlamaIndex Workflows, CrewAI) will converge or remain specialized.
- **Falsifiability:** New primary benchmarks on extraction accuracy with provenance, or major vendor shifts in BI/agent tooling, would revise maturity assessments.

## 2. Lens findings

### 2.1 Skills

**Definition and scope.** Discrete competencies required to move evidence into structured, queryable, analyzable form and back into research. Distinct from job titles.

**Core capabilities.** Research synthesis; information extraction (NER, relation extraction, table/structure extraction); data modeling (relational, dimensional, ontological); ontology/taxonomy design; normalization (entity resolution, type coercion, schema alignment); SQL; DuckDB; pandas/Polars; visualization; provenance tracking; agent orchestration.

**Workflow position.** Skills map across the entire chain; extraction, modeling, and provenance are highest-leverage.

**Relationships.** Used_in Workflow; required_by Market positions; implemented_via Technology/Software.

**Representative examples.**  
- SQL + DuckDB for direct file querying (CSV/Parquet/JSON).  
- dbt models + tests for normalization and lineage.  
- LLM prompting + schema enforcement for extraction.  
- PROV-style or nanopublication patterns for provenance.

**Trade-offs / failure modes.** Over-reliance on LLM extraction without human verification produces silent errors; pure classical NLP fails on novel domains; missing provenance breaks downstream trust.

**Evidence confidence:** High (official docs + academic surveys).

### 2.3 Technology

**Definition and scope.** Languages, runtimes, formats, and primitives that implement the workflow.

**Core entities.** Python; SQL; DuckDB (in-process OLAP); pandas/Polars (DataFrames); notebooks (Jupyter); APIs; scraping/browser automation; LLMs + embeddings; graph technologies (RDF, property graphs); data formats (CSV, Parquet, JSON, Arrow); databases (embedded, warehouse, lakehouse).

**Workflow position.**  
- Extraction/Structured: LLMs, embeddings, scraping.  
- Normalization/Database: SQL, DuckDB, Parquet/Arrow.  
- Query/Analysis: SQL, DataFrames, notebooks.  
- Visualization: libraries on top of the above.

**Key documented facts.**  
- DuckDB: embedded, vectorized OLAP, ACID, direct file querying, Python/R integrations, extensions (DuckLake for lakehouse metadata).  
- Polars: Rust + Arrow, lazy + streaming, multi-threaded by default; consistently faster and more memory-efficient than pandas on large workloads.  
- pandas remains the ecosystem default for interactive/small-data work.

**Trade-offs.** Local (DuckDB/Polars) vs shared governed (warehouse); eager (pandas) vs lazy/optimized (Polars/DuckDB); classical NLP vs LLM extraction (cost, determinism, provenance).

**Evidence confidence:** High (official DuckDB, Polars, pandas, Jupyter documentation and benchmarks).

### 2.4 Software

**Definition and scope.** Concrete packages and platforms.

**Core entities.**  
- Analytical engines: DuckDB, pandas, Polars.  
- Notebooks: Jupyter.  
- Transformation: dbt (T in ELT only).  
- BI/Visualization: Metabase (ease-of-use, non-technical), Apache Superset (SQL-first, extensible, more chart types).  
- Orchestration/Agents: LangChain/LangGraph, LlamaIndex (Workflows, document agents), CrewAI (role-based).  
- Extraction: Unstructured, LlamaParse, spaCy/GLiNER-class tools, custom LLM pipelines.

**Workflow position.** Direct implementers of Technology at each stage.

**Trade-offs (documented).**  
- Metabase vs Superset: Metabase wins on non-technical self-service and managed options; Superset on power, chart variety, pure Apache license, free enterprise auth.  
- Polars vs pandas: Polars preferred for new large-scale pipelines; pandas for ecosystem depth and small interactive work.  
- Agent frameworks: LlamaIndex strongest on document/RAG; LangGraph on complex stateful orchestration; CrewAI on simple role-based teams.

**Evidence confidence:** High for core tools; Medium for agent frameworks (rapid evolution).

### 2.5 Companies

**Definition and scope.** Employers, vendors, foundations, consultancies, research orgs active in the cluster.

**Examples (non-exhaustive, from product pages and hiring signals).**  
- Foundations/OSS: DuckDB Foundation, Apache (Superset), Project Jupyter, dbt Labs (open-core).  
- Vendors: MotherDuck (DuckDB cloud), Metabase Inc., Unstructured, LlamaIndex, LangChain, Observable.  
- Employers: any data-intensive org hiring Analytics Engineers, Knowledge Engineers, or AI workflow roles (tech, finance, healthcare, professional services).  
- Research: academic groups producing EvidenceBench, EvidenceNet, provenance papers.

**Relationships.** Produce Software/Products; hire for Market positions; sometimes govern Methodologies.

**Evidence confidence:** Medium (hiring is fluid; vendor claims require discounting).

### 2.7 Methodologies

**Definition and scope.** Protocols and patterns that govern stages.

- Research protocols (systematic review, PICO for evidence-based medicine).  
- ETL vs ELT (dbt is ELT-native).  
- Data modeling (dimensional, medallion/bronze-silver-gold, ontological).  
- Information extraction pipelines (rule → classical ML → transformer → LLM-assisted).  
- Evidence & provenance systems (PROV-O, nanopublications, knowledge provenance extensions).  
- Analytical workflows (exploratory notebooks → reproducible pipelines).

**Position.** Govern Workflow stages; especially Extraction, Normalization, Provenance.

**Trade-offs.** Deterministic classical methods vs flexible LLM methods; strict provenance vs speed.

**Evidence confidence:** High (academic + dbt docs).

### 2.8 Workflows

**Definition and scope.** The end-to-end research-to-data loop and its variants.

**Core loop.** Research → Evidence collection → Extraction → Structured representation → Normalization → Database/storage → Query → Analysis → Visualization → Interpretation → New research, with Agent iteration wrapping or accelerating any stage.

**Inputs/outputs, quality gates, feedback.** See Section 3.

**Evidence confidence:** High (synthesized from tool docs and role literature; the loop itself is a stable pattern).

### 2.9 Agents

**Definition and scope.** LLM-powered or hybrid systems that perform or coordinate stages.

| Agent type | Task | Required tools/state | Handoffs | Failure modes |
|------------|------|----------------------|----------|---------------|
| Research agent | Literature search, synthesis | Web search, retrieval, memory | → Extraction or Writing | Incomplete coverage, citation hallucination |
| Extraction agent | Structured extraction from text/docs | Parsers, schemas, LLM | → Normalization | Schema drift, missed entities, non-determinism |
| Coding / data-cleaning agent | Transform, clean, model | Code interpreter, DuckDB/pandas, tests | → Database | Incorrect transformations, silent data loss |
| Analytical agent | Query + insight generation | SQL/DataFrame tools, BI | → Visualization / Interpretation | Wrong metrics, over-interpretation |
| Orchestration agent | Plan, route, verify | Multi-agent frameworks, state | Coordinates all | Cascading errors, unverified intermediate results |

**Position.** Perform or govern any stage; strongest current value in Extraction, Research, and bounded Analysis.

**Evidence confidence:** Medium (framework docs strong; production reliability still emerging).

## 6. Research gaps and next investigations

1. **Provenance standards for LLM-derived claims** — Current PROV/nanopublication work is academic; production adoption and tooling are thin. Next: survey production systems and emerging standards.
2. **Extraction quality under realistic multi-source conditions** — Benchmarks exist (EvidenceBench, Unstructured tables) but multi-source conflict resolution and cost curves need more independent data.
3. **Role boundary stability** — Knowledge Engineer and AI/Agent Workflow Specialist titles are still expanding. Next: systematic job-posting corpus analysis over 12–24 months.
4. **Agent verification patterns** — Failure modes are acknowledged; systematic evaluation frameworks and human-in-the-loop patterns are under-documented.
5. **DuckLake / lakehouse metadata evolution** — Recent; long-term adoption vs Iceberg/Delta needs monitoring.
6. **Cost and environmental impact of LLM extraction at scale** — Missing from most primary sources.
7. **Observable and other reactive notebooks** as alternatives to Jupyter in production analytical workflows.

**Highest-value next searches:**  
- Primary papers and standards on knowledge provenance for aggregated claims.  
- Independent extraction benchmarks with provenance metrics.  
- Longitudinal job-posting analysis for Knowledge Engineer / Agent roles.  
- Production case studies of LangGraph / LlamaIndex in research-to-data pipelines.
