**PROV-K Ontology – Detailed Overview**

**Official resources**  
- Documentation: https://prov-k.dei.unipd.it/ontology/ (and https://w3id.org/PROV-K/ontology/)  
- Serializations: OWL and Turtle available on Zenodo (record 15187372, version 1.0, 2025-04-10)  
- Authors: Stefano Marchesin, Laura Menotti, Gianmaria Silvello (University of Padua)  
- Imports: PROV-O (W3C) and SKOS  
- Namespace prefix for schema terms: `https://w3id.org/PROV-K/ontology/schema/`  
- Funding context: EU HEREDITARY project  

**Purpose**  
PROV-K extends the W3C PROV Ontology (PROV-O) to represent **knowledge provenance** for assertions derived from *multiple sources* via aggregation, information extraction, or truth-discovery algorithms. Standard PROV-O and classic nanopublications handle single-source provenance well; PROV-K adds explicit support for ensembles of supporting/conflicting evidence, assigned vs. trusted truth values, reliability criteria, and trust relationships. It is designed both as the vocabulary for the optional “knowledge provenance” named graph in extended nanopublications and as a standalone ontology.

### Four main conceptual areas

1. **Propositions** (core focal point)  
2. **Digital Signature and Information Sources**  
3. **Trust Relationships**  
4. **Truth Values** (including reliability assessment)

### Key Classes

**Proposition hierarchy** (all ultimately under `prov:Entity`):
- `Proposition` – Declarative sentence that is either true or false.  
- `AssertedProposition` – Independent assertion (not derived from others).  
- `DependentProposition` – Truth value depends on other propositions.  
  - `CompositeProposition`  
    - `ANDProposition`, `ORProposition`, `NEGProposition`  
  - `DerivedProposition` (logical conclusion from premises)  
  - `EquivalentProposition` (reproduction of another proposition)  
- Reuses `SIO_000113` (sentence) for textual evidence.

**Truth-value and reliability classes**:
- `TruthValue` (subclasses of `prov:InstantaneousEvent`)  
  - `AssignedTruthValue` (assigned by the assertion’s creator)  
    - `ReliableFact`  
    - (implied counterpart for unreliable)  
  - `TrustedTruthValue` (assigned/trusted by an external agent)  
- `ReliabilityCondition`  
  - `SufficiencyCondition` / `SufficiencyCriteria`  
  - `ConsistencyCondition` / `ConsistencyCriteria`  
- `UnreliableFact`  
  - `InsufficientEvidence`  
  - `ConstrastingEvidence` (note: spelling in the ontology)

**Trust and signature**:
- `TrustRelationship`  
  - `PropositionTrustRelationship` (agent trusts an assertion)  
  - `InfoCreatorTrustRelationship` (agent trusts an information creator)  
- `Signature`  
- `Field` (knowledge domain/field)

### Key Object Properties

- `hasTruthValue` – Links a Proposition to a TruthValue (Assigned or Trusted).  
- `supportedBy` – Proposition → sentence(s) that support it (inverse of `hycl:claims`).  
- `conflictingWith` – Proposition → sentence(s) that conflict with it.  
- `hasSignature` – Proposition → Signature.  
- `assignsTrustedTruthValue` – Agent → TrustedTruthValue (functional).  
- `trustedProposition` / `trustedInfoCreator` / `trustorAgent` – Components of trust relationships.  
- `sufficiencyCriteria` / `consistencyCriteria` – Link reliability conditions.  
- `hasSufficiencyScore` / `hasConsistencyScore` – Scores for reliability assessment.  
- `unmetCondition` – Links to unmet ReliabilityCondition(s).  
- `dependsOn` – For dependent propositions.

### Key Data Properties

- `truthValue` – Literal value (`true` / `false` / `unknown`).  
- `certaintyDegree` / `assignedCertaintyDegree` / `assignedCertaintyDegreeSupport` – Numeric confidence.  
- `conditionScore` / `conditionThreshold` – For sufficiency/consistency evaluation.  
- `digitalSignature` / `signatureStatus` – Signature details.  
- `unreliabilityReason` – Textual explanation.

### Design principles and usage notes

- Built on theoretical foundations of Static and Dynamic Knowledge Provenance literature.  
- Backward-compatible with standard nanopublications: the knowledge-provenance graph is optional.  
- Domain-specific reliability criteria can be added (the CORE gene–cancer system uses sufficiency + consistency criteria).  
- Supports timestamps on truth values and trust relationships (dynamic aspect).  
- Can be used independently of nanopublications for any multi-source assertion scenario.  
- Real deployment: ~197,511 gene-expression–cancer associations (GCS) from the CORE system published as extended nanopublications using PROV-K.  

**Example pattern (conceptual)**:
```turtle
:assertion a pk:Proposition ;
    pk:supportedBy :sentence1, :sentence2 ;
    pk:conflictingWith :sentence3 ;
    pk:hasTruthValue :tv1 .

:tv1 a pk:AssignedTruthValue, pk:ReliableFact ;
    pk:truthValue "true" ;
    pk:assignedCertaintyDegree 0.87 .
```

### Relation to the broader research-to-data workflow

PROV-K directly addresses the **Evidence → Extraction → Structured representation → Provenance** stages when claims are aggregated from multiple sources (classic single-source PROV is insufficient). It provides the formal vocabulary needed for agent-produced or IE-produced claims to carry verifiable multi-source lineage, support/conflict sets, and trust assessments—critical for later Query, Analysis, Interpretation, and Agent iteration loops.

**Maturity / limitations**  
- Version 1.0 (2025); documentation is generated (some introductory text is still placeholder).  
- Strongly grounded in PROV-O and real biomedical use cases.  
- Domain extensions for reliability criteria are expected.  
- Tooling beyond the ontology files and the CoreKB deployment is still emerging.

**Primary evidence confidence**: High (official ontology documentation page + Zenodo release + peer-reviewed paper describing the model and its application).
