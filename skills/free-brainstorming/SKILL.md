# Free Brainstorming

Facilitates external, independent brainstorming on universal research problems, free from self-referential projection or focus on internal project artifacts. Distilled from `Rules and Regulations/Protocols/FreeBrainstorming.md`.

## When to use this skill

- Brainstorming research ideas with external validity
- Exploring universal problems across domains
- Generating independent research directions
- Asked to "brainstorm research ideas" or "explore external problems"
- When you need ideas that don't depend on this project's existence

## Core Principles

1. **External frame of reference** — focus on universal problems outside this project
2. **Broad scope and independence** — topics must have clear external relevance
3. **No internal projection** — never frame questions as "if only we had X"
4. **Actionable independence** — outputs should be applicable regardless of this project

## The Process

### Step 1: Topic Generation (External Focus)

1. **External triggers** — identify sources:
   - News articles
   - Policy documents
   - Industry reports
   - Academic publications
   - Standard bodies

2. **Cross-domain mapping** — identify 5+ external domains:
   - Healthcare, finance, climate, transportation, education, etc.

3. **Universal problems** — list 10-20 problems that exist across multiple domains:
   - Privacy, bias, interpretability, reproducibility, scalability, ethics

### Step 2: Problem Reframing

1. **Remove internal context** — describe each problem as if the project didn't exist
2. **External benchmarks** — reference established frameworks in other fields
3. **Scope creep guard** — reject "how would this project do it differently" questions

### Step 3: Solution Exploration (External Validity)

1. **Cross-reference** — compare against solutions in other domains, not this project's approach
2. **Generalization tests** — "Would this solution work for a hospital, a bank, and a transportation authority simultaneously?"
3. **External validation** — use peer-reviewed literature, industry standards, regulatory requirements

### Step 4: Deliverable Format

Produce a research idea document with this structure:

```markdown
# External Research Idea: [Universal Problem]

## External Context
- Domain: [Healthcare/Finance/etc.]
- Established Solutions: [List 3-5 approaches from other fields]
- Gaps Identified: [2-3 missing elements in external approaches]

## Proposed Approach
- Methodology: [Borrowed/adapted from external domain]
- Key Innovations: [Universal innovations, not "new for us"]
- External Validation: [Evidence from other domains]

## Expected Impact
- Cross-domain applicability
- Reproducible methodology
- Actionable for external stakeholders

## Limitations (External Only)
- Scope deliberately bounded to universal problem
- No internal project dependencies
```

## Quality Gates

- [ ] **External relevance** — can be understood and applied by organizations outside this project?
- [ ] **Reproducibility** — can a team with no internal knowledge implement the approach?
- [ ] **Impact** — measurable benefits in the external domain, not internal efficiency
- [ ] **Ethics** — no references to internal ethical frameworks unless universally accepted principles
- [ ] **Independence** — no idea requires internal project changes to be implemented
- [ ] **Clarity** — each idea can be understood by someone unfamiliar with this project

## Exit Criteria

A brainstorming session is complete when:
- All ideas have at least one external reference point (publication, standard, industry practice)
- No idea requires internal project changes to be implemented
- Each idea can be understood by someone unfamiliar with this project

## Tips

- When internal references creep in, ask: "Would this make sense if the project never existed?"
- Use "external stakeholder" framing: "How would a public health agency approach this problem?"
- Keep a "projection detector" checklist:
  - Am I describing how **we** would do something?
  - Am I analyzing our **internal** weaknesses?
  - Am I focusing on **our** needs vs. **universal** needs?
  - Should this exist even if **no one** had this project?
